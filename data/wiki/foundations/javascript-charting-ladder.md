# JavaScript Charting Ladder

Every web chart, including those generated from Python, is JavaScript in a browser. Three libraries sit at different abstraction levels.

| | D3 | Vega-Lite | Observable Plot |
|---|---|---|---|
| You describe | Elements and geometry | A JSON specification | Marks and options |
| Good at | Anything, new forms, bespoke transitions | Portable specs, linked views, generated charts | Fast exploration in JavaScript |
| Fights you on | Time; everything is your job | Pixel-level annotation | Bespoke interaction |
| Python route | None | Altair | None directly |
| Lines for one chart (this setup) | 67 | 33, mostly styling | 24 |

Line counts are one chart with custom styling, an illustration of the ladder, not a benchmark.

**D3** is a toolkit for binding data to document elements plus geometry (scales, axes, line generators, layouts); it has no `barChart()`. Scales are ordinary functions (`y(30)` returns pixels). The core idea is the **data join**: `selectAll("path").data(series).join("path")` makes the set of elements match the list, creating, updating and removing as needed, so re-running with new data makes the page follow. Hover targets work better as large invisible circles per point (or a Voronoi overlay for dense points) than on a 2-pixel line.

**Vega-Lite** is the [[Grammar of Graphics]] as JSON, compiled to a longer Vega spec with scales, axes and legend derived from field types. The spec is plain JSON, so it can be stored, generated by a server or an LLM, and validated against a schema. Altair generates the same JSON.

**Observable Plot** is a concise API over D3; `Plot.lineY` groups by `stroke`, and `Plot.selectLast` keeps the last row per group, making end labels one mark.

## Choosing

Use Altair or plotly from Python while you can; Vega-Lite when a product team embeds a chart defined by data; Plot when already in JavaScript and wanting speed; D3 for a chart needing custom design that is worth days of someone's time. D3 stops looking expensive where the others cannot do it at all.

## Pitfalls

- **UTC versus local time.** `new Date("2023-01-01")` parses as UTC while time scales and formatters work in local time, so ticks drift by a day or a month. Use UTC throughout (`scaleUtc`, `utcFormat`, `scale: {type: "utc"}`).
- **Testing without a browser.** jsdom renders the DOM and lets you fire events and assert, but has no layout engine, so anything measuring text (`getBBox`) needs a real browser.
- Standalone SVG needs an explicit `xmlns` for non-browser SVG tools; ES modules refuse to load from `file://`, so serve the folder.
- Colouring text like the series fails contrast; use ink.
- Reaching for D3 first.
