# Diversity Seeding for Synthetic Data

Uses: eval sets, training data for a small model (distillation), test fixtures. **The
core problem is diversity** — even at high temperature, models produce repetitive,
trope-heavy samples. Put the randomness **in the prompt**.

## Pattern 1 — combinatorial seeding (TinyStories)

Eldan et al. (2023) sampled a verb, noun and adjective from a ~1,500-word child vocabulary
plus story features into every prompt. Recipe:

1. Identify the dimensions that should vary (topic, audience, length, tone, **label**).
2. Build value lists per dimension (by hand or generated).
3. Sample a combination per request; temperature above default, below maximum.
4. **A seeded label is a free label** — "write a negative review" yields a labelled negative.

## Pattern 2 — hierarchical generation

Generate intermediate pieces first (a summary, a must-include sentence, a feature list, a
topic list), then feed them into the final request. Asking for several examples per topic
in one generation gives more variety than repeated calls at temperature > 0.

## Pattern 3 — audience as lever (phi-1)

Gunasekar et al. (2023) generated ~1B tokens of textbook-style Python varying **topic** and
**target audience**; a 1.3B model trained on it rivalled models ten times larger on
HumanEval. Audience is a cheap diversity lever — the same topic for a high-schooler, an
undergraduate and a PhD candidate reads very differently.

## Pattern 4 — synthetic queries for retrieval (Promptagator)

Dai et al. (2022): **8 labelled examples plus an unlabelled corpus** suffice. Few-shot
prompt an LLM to write a query per document, train the retriever on (query, document)
pairs. Name the search intent (supporting vs counter-argument) since relevance depends on
it; label ~20 examples and randomly sample 2–8 per prompt. ~50k synthetic pairs matched a
model trained on comparable human labels. See [[Synthetic Dataset Generation for RAG Eval]].

## Pitfalls

- **Distribution mismatch** — skewed seeds give skewed data, which then biases any
  few-shot use of it ([[Few-Shot Prompting]]).
- **Model bias** — data generated by model A favours model A in evals ([[Evaluating Prompts]]).
- **Quality drift** — dedupe, judge-filter, spot-check by hand.
- **Aligned voice** — RLHF flattens style; for realistic user-like text consider a base
  model or a strong persona ([[Prompts as Document Completion]]).
