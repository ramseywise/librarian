# Fix the Generator, Not the Generated Record

nonprofit-success-ai's design of record is an HTML document regenerated by a
`/design-system` skill from the PRD and specs. An external review raised twenty points.
The tempting response is to patch the HTML, but the next regeneration wipes hand-edits.
The response plan instead treated the document as build output.

## Sort findings by where the fix belongs

| Category | Meaning | Fix lands in |
|---|---|---|
| A | Already in the specs, missing from the HTML | The **skill** (generator bug, not a design gap) |
| B | Already tracked as a delta/registry row | Nothing new; cite the row |
| C | Genuinely missing | The **specs** |
| D | Endorsements | Record them, because they validate earlier skill rules |

Category A was the surprise. A four-rung failure ladder, idempotency rules, a model gateway
and an eval subsystem all existed in specs, but the generator never surfaced them. The
rule that came out of it: **check the spec tree against the plates. A spec section with no
plate is either a missing plate or a spec that should be deleted.**

## Execution semantics need a required plate

The reviewer's most valuable findings were all execution semantics:
- the state machine;
- idempotency;
- concurrency;
- the failure taxonomy;
- the realtime/event-bus boundary.

A component-by-component design leaves these out because no single component owns them.
The skill now requires a semantics plate where each item is either specified or
**explicitly deferred**. Deferral is a valid answer; silence is not. (Concurrency:
deliberately deferred, a unique constraint as backstop, and the lock named for if it ever
matters.)

## Make the skill's rules executable

- **Prose rules did not survive; a template will.** "Include a diagram per plate" produced
  zero diagrams. A mandatory inline SVG skeleton to copy produced eight.
- **Never cite your own failed output as the reference.** The skill pointed at its earlier
  zero-diagram output as the thing to match, which taught the failure. The skill now
  points at a hand-made reference and explicitly flags the old file as "an earlier
  output of this skill, not a reference".
- **The publication checklist must discriminate.** It is eight greppable counts (svg,
  figcaption, anchors, cross-links, status pills, plate numbers…). It was validated by
  showing every count reads **zero on the failed document and passes on the reference**.
  If a check passes on both, it describes rather than tests.
- **Skill edits land first**, so one regeneration picks up everything.

## Two documents, one writer each

Keep a frozen PRD (the decision record) separate from a design of record that is
re-verified against the code. The two have different lifecycles, `§N` section numbers act
as a stable API that other docs cite, and each file has one writer.
