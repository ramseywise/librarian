# JARVIS-1 Multimodal Experience Memory

JARVIS-1 (a 2023 preprint from the CraftJarvis team) is an open-world Minecraft agent that plans with a multimodal language model and a memory of what has worked. The extraction notes it is an experience-memory and retrieval-augmented planning paper, not an operating-system-style paging design, and it sits beside Voyager and Generative Agents in kind.

## The memory loop

- **Store.** A list of dictionaries, each with a task, a state and a plan. Keys are multimodal (the task plus the observation when the entry was made) and values are plans that executed successfully. Only successes are stored.
- **Retrieve in two stages.** An LLM first does backward search, decomposing the current task into depth-bounded sub-goals and asking which related tasks might help. Then a CLIP text match filters candidate entries by a confidence threshold, and candidates are ranked by visual-state similarity. The top entry per sub-goal is used.
- **Plan and repair.** Plans are code-like action lists. A self-check step simulates the inventory before execution, and self-explain uses environment feedback to locate the fault and re-plan.
- **Grow.** A planner picks tasks from a pool in a self-instruct curriculum, parallel agents share one memory, and memory grows up to a capacity limit. Of the curricula compared, the paper reports (self-reported; success against game time in the Minecraft setup below) that one generated by GPT did best, ahead of human-written and random ones. After four epochs of learning the paper reports (self-reported) that memory held 425 successful trajectories.

## Reported results (self-reported)

Setup: survival mode in Minecraft 1.16.5, eleven task groups from the Minecraft Universe Benchmark (over 200 tasks), a GPT planner, and a memory built during four training epochs ahead of evaluation; each task ran with 30 or more seeds.

- Diamond-group success averages 8.99% against 2.42% for the same planner without memory (DEPS), and re-planning needs 2 to 3 rounds against more than 6.
- Diamond pickaxe success rises from 6.2% to 12.5% as game time grows from 20 to 60 minutes with no gradient update, while the VPT-RL baseline goes from 2.5% to 3%.
- The paper says reasoning before retrieval improves retrieval and multimodal keys beat text-only, but the extraction could not recover the figure values.
- With memory, ChatGPT reaches nearly the same success as GPT-4.

## Limits

- Internal inconsistency noted by the extraction: the abstract and conclusion claim a five-fold gain on the diamond pickaxe, while the body says the rate "more than doubled" (6.22% against 2.5% within 20 minutes); only the 60-minute figure gets near five-fold.
- The authors concede the controller, not planner or memory, is the bottleneck on diamond tasks.
- Only successes are kept, with no eviction, summarisation or staleness handling. The setting is easier than normal play (peaceful difficulty, permanent daytime, kept inventory, night vision), and Minecraft is the only domain.
- Memory is filled before evaluation on the same task pool, so transfer is confounded with task overlap. Ablation values exist only in figures, and no cost or latency is reported.
