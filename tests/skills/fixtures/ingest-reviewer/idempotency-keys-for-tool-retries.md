# Idempotency Keys for Agent Tool Retries

A timeout does not tell an agent whether its tool call failed. In a dispatch agent built for
Tarnfield Logistics, retries after timeouts printed the same shipment label twice, because
the carrier had often accepted the original call.

The caller now generates a key per request and stores it in Redis for 24 hours. A repeat
with a known key gets back the saved result, and the carrier sees one call.

A circuit breaker, as described by Michael Nygard in Release It!, wraps the tool and trips
after three consecutive failures.

The change cut average tool latency by 37 percent. Nobody reported a duplicate during the
following two weeks.
